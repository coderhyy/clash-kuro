# Fixed internal DNS route ledger candidate

Only tun-routes.m and tun-routes.test.m change. No shared source, Core/App/helper execution, PF_ROUTE/sysctl, installation, or system networking.

API: `KuroInternalDNSRouteCandidate(association)` returns exactly IPv4 .2/32 plus IPv6 ::2/128. `KuroSessionRouteCandidate(association)` returns that ordered prefix followed by the existing fixed four /1 routes. `continueSessionRoutesForSession:interface:ownership:error:` takes no route input. It requires this same serial actor's successfully persisted complete exact-host2 receipt, unchanged journal bytes/session/full association, unique exact host readback and live held owner. It refuses conflicting /1 destinations. It consumes the one-shot authority, publishes+syncs combined6/applied2 before any /1 add, then independently reads back and persists each remaining applied receipt. A failure requires cleanup; it never resumes appending a six-entry record or adopts another actor/old4 receipt.

`confirmInstalledSession` now rechecks original journal bytes and always syncs its directory after exact current readback/live owner. No pending-receipt state was added. Actual failed final receipt dirsync can no longer be mistaken for confirmed durability by a subsequent call while sync still fails.

Validation: strict production compile-only exit0; focused actual route implementation tests exit0 (20 continuation cases, 4 host-preparation failure cases, old4/host2/combined6 after-reap and restart absence-only behavior, plus existing parser/kernel flags/12 ownership/2 durability cases). Failure coverage includes wrong actor, old4/order/journal changes, duplicate/missing/changed host, existing split, unknown/exited owner/snapshot, publish refusal, actual merged-plan rename then dirsync failure, lost add acknowledgment, modified readback, owner loss, and actual final receipt rename then repeated sync failure. The fake add hook verifies the combined plan and applied prefix were already successfully synced before each /1 add.

Deterministic durability RED/GREEN uses an actual final receipt publication with the directory sync injected to fail, leaving applied4 on disk. Original production confirmation returns YES/YES without retrying sync (exit1 proof failure). New code returns NO/NO while sync fails, then YES only after sync succeeds (exit0). See verification.json and durability-{red,green}.stdout.log. Coordinator and seven actual socket admission-chain integration belong to tun_spec/main and are not claimed by these route-only tests.

Old routes-v1 parser and recovery schema are unchanged. Four-entry receipts remain recoverable. Host2 and combined6 after-reap/restart remain absence-only; any remaining recorded key preserves journal without deletes. New write helpers do not grant restart PID/interface adoption, arbitrary append/RPC, or new deletion authority. Real Darwin host-route behavior and end-to-end internal DNS still require the separately authorized network window; fixtures do not establish them.
