# Independent recovered stop checkpoint — isolated candidate

Baseline native snapshot: observed shared commit e2243bbb6bc73f03b01c93e264c2c44917456e74. Shared subsequently advanced; apply only the seven-file diff, never copy the entire native tree.

- `KuroRestartEvidenceCheckpoint(record, originalOwnerBytes, stillAbsent, error)` is a new private fresh-recovery callback. The older overload supplies nil. No-owner recovery never calls it. The callback occurs after exact work cleanup; original bytes are retained by the session, including a recovered-cache checkpoint if that atomically updated the owner.
- `KuroProductionNetwork recoverRecordedSession:error:` first uses existing exact DNS/route-absence recovery, then reads the actual complete route and DNS backends. It rejects read/shape errors, RTF_PROTO2, active prefix-1 routes, routes overlapping fixed internal utun/DNS addresses, Kuro DNS UUID keys, and remaining route/DNS journals. This observes current owned absence; it does not reconstruct historical writes or held reap. Existing no-CAS/third-party-change limits remain.
- `hooks.recoveredNetworkEvidence(record,error)` is wired by ProductionService to the real coordinator; no public RPC or UI change. Fresh installed owners still pass the exact installed writer validator and repeated Core/helper/group absence observations. Legacy recovery gets no new authority. Existing format-3 replay also requires actual backend readback, including the no-owner resync path.
- Format 3 (`kind:fixed-core-recovered`) has 13 closed keys: format, kind, release, helperSHA256, coreSHA256, manifestSHA256, inventorySHA256, installedSHA256, session, ownerJSON, ownerSHA256, network, workAbsent. `ownerJSON` stores the original bytes as UTF-8, not a reserialized object. Its source installation identity/runtime/cache-origin schema must bind this current protected installation. It has no process/childReaped/wait-status field and is not accepted by KuroCompletedStopEvidence.
- `network` has 5 closed keys: format=1, kind=current-owned-absence, session, routesOff=true, dnsOff=true. This is not held format-1 historical journal evidence.
- Before owner unlink: exact bytes/installation/writer absence + work/network footprints are checked, proof file and State directory are durably synced, actual route/DNS readback is repeated, then session repeats original owner/writer/work/network checks before unlink and directory sync. Persistence or changed evidence leaves the owner. An existing proof can only be exactly re-synced; unknown/partial/mismatched proof is never overwritten. Actual encoded proof must fit the consumer 64KiB limit before any write; the closed original owner is validated before nested reads (arrays/null cannot trigger keyed-subscript exceptions).
- neverStarted stays sticky. A true-history recovered installation receives no format 3. No owner means no newly generated proof. Revoke-before-start handles validated format 3 through the common binding validator.
- Uninstall/upgrade admit the new separate proof through their current common receipt validator. All existing job/ServiceLock/unknown owner/work/network/State/file gates stay. The decoded original receipt digest removes only the later uninstallJSON approval (upgradeJSON remains), so partial uninstall retry does not recursively invalidate its own original source identity. All native receipt writers already use canonical JSONData.

Verification is ordinary UID only: 23 actual temporary install/production-writer/recovery/consumer chains plus 8 late actual-backend-fixture readback cases; strict production/test compile; full native fixtures with KURO_SKIP_CORE_SYNTAX=1; actual temporary upgrade CLI matrix (102 interruptions). Process/group and Darwin route/DNS observations are injected; no real Core, -t, launchctl, install, root service or system network operation was run. A sandbox Unix-socket denial was rerun with approval for ordinary-UID temporary fixtures only.

Important remaining boundary: a crash with no complete owner and no existing valid proof still cannot manufacture uninstall authority. Unknown/changed/truncated objects remain blocked/preserved. This does not claim hostile-root resistance or support arbitrary detached writers beyond the approved fixed-Core finite writer contract. Real root/TUN crash recovery and real upgrade remain separate acceptance work.
