# macOS 持久 helper 安装路线比较

Status: resolved（路线已选择；技术安全设计与实现另 04）
日期：2026-11-04。依据 [02 平台研究](platform-feasibility.md) 的一手证据，不新增大规模搜索或执行安装。产品边界以 [ADR-0014](../../docs/adr/0014-macos-tun-lifecycle.md) 为准。

## 已选择路线

维护者已按 [ADR-0015](../../docs/adr/0015-macos-traditional-privileged-helper.md) 选择 **管理员安装传统 LaunchDaemon + 小型 helper**，不依赖付费会员；SMAppService、Developer ID 和公证延期，不再以路线或付费身份待选阻塞。禁止 setuid Core、任意 root 命令或路径接口。安装不等于启动/继续代理；ADR-0014 的互斥、退出、异常恢复及卸载边界继续有效。

04 承接 `macos-helper-security.md` 的具体安全设计并等待主会话接受：授权入口、受保护路径、产物及调用者认证、最小 IPC、升级/卸载及失败恢复。路线确定不等于这些已验证，真实系统操作仍须用户明确说“开始”。正常重开先残留检查、保持 TUN 关闭并手动开启已由 ADR-0016 批准；IPv4-only 与网络模板仍未接受，参数归 01。

## 历史建议与选型背景（已被当前路线决定取代）

建议首选 **SMAppService 内嵌 LaunchDaemon + 正式签名/公证**：系统提供注册/注销、管理员批准和授权状态，组件与 App bundle 关联，固定 Electron45 已有 daemonService 注册入口。代价是当前 ad-hoc/未公证包不满足官方 SDK 契约，需要真实身份及对应打包工作。这是比较阶段的建议，已由上述传统路线决定取代；保留以解释一手证据和取舍，不作为当前实施建议。

比较阶段将 **管理员安装传统 LaunchDaemon** 作为不准备正式身份时的候选，现已被明确选择；其管理员安装、受保护路径、客户鉴别及升级卸载成本更高，不是绕过安全校验的捷径。不能因为传统系统机制存在，就承诺当前未签名产品已经可安全发布。

比较阶段曾请求路线和身份选择，现已由维护者选择传统路线解决，不再请求付费身份。最低目标 macOS 由 04 核对，正常重开不自动启用已批准；DNS/路由参数归 01 保留待确认，不擅自赋值。

## 对比（证实与待验证分开）

| 方面 | SMAppService LaunchDaemon | 管理员安装传统 LaunchDaemon |
| --- | --- | --- |
| 官方机制 | macOS13+ SMAppService 支持登记内嵌 daemon；plist 位于 Contents/Library/LaunchDaemons（02 A2/A3） | Apple 归档 launchd 指南描述 /Library/LaunchDaemons，SDK声明传统机制仍受文件权限保护（02 A5/A7）；不能把归档示例当当前产品验收 |
| 授权 | register 后须管理员在系统设置批准，系统可报告状态（02 A4/A6）；具体 UI/拒绝和再次批准须实测 | 写受保护位置及加载系统级 job 需要授权安装流程；具体安装器/授权 API 未选，不能采用静默 sudo 或将 GUI 全程以 root 运行 |
| 签名/公证 | 官方 SDK27写明应用须代码签名、含 LaunchDaemon 的应用须公证（02 A5）；当前包不足，真实证书身份未提供 | 现有一手资料没有给出与 SMAppService 相同的全局公证前置声明；这不证明 Gatekeeper/当前系统/安全分发已满足。可执行身份与安装完整性仍必须设计 |
| 调用者认证 | 注册/批准不等于每次 RPC 鉴权。需选可验证客户端身份、严格操作/参数，私有 socket/XPC 或其他协议尚未决定；仅同团队签名不自动完成鉴权 | 管理员安装不授权任意本地客户端。须独立验证客户身份和安装产物/请求范围；无法提供稳定身份时，不能开放任意用户到 root 的 RPC |
| 保护位置 | 官方机制要求 daemon plist 内嵌 App；BundleProgram 可指包内 helper（02 A5）。实际 App 安装目录及可写性、root 读取用户配置、替换竞争须验证；不能把 bundle 路径当完整安全证明 | 传统 plist 位于 /Library/LaunchDaemons；helper 实际受保护路径未选，安装应仅允许管理员写并验证身份/原子替换。不得直接将用户可写开发目录/Core 任意路径交给 root 执行 |
| Core/网络生命周期 | helper 持久安装可以保留；启动/业务转发必须绑定批准的 App 会话，退出停准确 Core/TUN、只清理本应用网络。开机 bootstrap 不等于允许开机代理 | 同样必须将安装状态与运行状态分开。不得默认 KeepAlive、系统开机自动代理或无限重启 Core；launchd job 的具体按需策略由 04 安全设计明确 |
| 升级 | SDK要求 plist/可执行文件更改后重新注册，建议可执行文件变更前 unregister（02 A5）；先停并确认旧 owner，再原子替换/重新登记，失败保留可诊断状态，具体协议待定 | 需要自管停止确认、原子安装、权限、版本兼容和加载；旧 owner 未确认退出不得并行新 writer。回滚/残留记录不能只用版本字符串冒充证据 |
| 显式卸载 | 提供停止准确 Core/TUN、确认本应用网络清理、注销服务的显式入口；系统注销不等于业务资源已清理（02 A2）。何时删包内外文件和权限拒绝分支须验证 | 提供授权卸载：先停/确认网络，再卸载 job、删除仅本产品拥有的 plist/helper；核验路径/身份，禁止通配误删。失败提示具体剩余状态并阻止新 writer |
| 失败/异常恢复 | 启动先检查本应用残留，确认归属/旧 writer 退出再恢复；未知提示并关门；异常后不自动启用。安装、批准、注销及恢复记录持久化失败各须测试 | 相同 ADR-0014 边界；授权取消/部分安装/加载失败/部分卸载须可识别并给安全处理入口。不得静默改第三方路由或删除未知文件“恢复” |
| 最低系统版本 | API已证实 macOS13+；本产品、Electron45与最终签名包的实际最低版本尚需核对，不能只以API availability宣布产品支持下限 | 归档证明机制长期存在，不证明本产品支持旧系统；最终最低版本由固定Electron/Core/打包及维护者目标共同约束，当前不声明旧版本兼容 |

## 两条路线共同的最小契约

- 明确有限操作、调用者、精确 helper/Core 身份、私有控制通道、路径/参数及用户可写配置边界；不实现通用 root 命令执行。
- 将已安装、已批准、正在运行、停止已确认、恢复未知分开；确认旧模式退出才启动新模式，订阅/Override 不能绕过最终 tun.enable 门禁。
- 退出 App 停 TUN/Core并清理本应用网络；持久安装可保留但不继续代理；异常不自动重新启用，下次启动先查/恢复残留，无法确认提示处理并关门。
- 正常重开先检查/恢复残留，保持 TUN 关闭，仅手动开启已由 ADR-0016 批准。DNS/路由参数也不在安装路线中选定。

## 已选传统路线的最小验证（尚未执行）

1. 纯/fake验证客户身份与错误请求拒绝、替换/路径负例、安装取消/部分失败、准确 owner、退出/卸载顺序、恢复未知关门。
2. 当前精确包检查产物身份、实际签名状态与保护位置（不要求 Developer ID/公证）；传统安装授权批准/拒绝、安装后不启代理、App退出停Core/TUN、旧网络读回、显式卸载与失败状态。
3. 升级时确认旧 owner 退出再启新版，避免并行 writer；异常残留在恢复前可观察，新启动恢复先于任何新启用。

第2/3项涉及人工系统操作，必须等维护者明确说“开始”后由主会话串行安排；真实安装、路由或恢复都尚未验收。Windows TUN与旧07恢复不作为macOS首版前置条件。

## 证据边界

本比较复用02的Apple SMAppService在线文档/SDK27头文件、固定Electron45 app API、固定mihomo/sing-tun源码，以及Apple归档launchd指南；每项原始链接见 [platform-feasibility.md](platform-feasibility.md)。没有将现代SDK合同推定成所有旧系统的实测，也没有把传统安装需要授权/受保护写入推定成现有App已实现安装器。身份验证、保护目录、最低目标系统、升级卸载和真实恢复均在已选传统路线实际实现/实验前保留未知；这些是 04 的具体技术与实验事项，不将 09 重新标为路线待选。
